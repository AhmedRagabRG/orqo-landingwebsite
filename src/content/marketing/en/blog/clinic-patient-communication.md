## Define the administrative scope
Start with the questions reception can answer from approved information: location, opening hours, offered services and how to request an appointment. List who maintains each answer and how staff will know it has changed.

Keep clinical questions on the clinic's approved referral path. A messaging workflow for administrative enquiries should not be treated as a diagnosis or treatment service. This guide suggests an operating process; it does not establish healthcare compliance for any software.

## Distinguish an enquiry from a booking
A person asking whether a slot is available has made an enquiry, not a confirmed appointment. The responsible staff member should check the scheduling system before confirming. Record the outcome clearly so the next employee does not make a conflicting promise.

If a software provider demonstrates calendar integration, test what it reads, what it writes and what happens when a slot changes. Until that setup is verified, keep the scheduling system authoritative and use the inbox for communication around it.

## Give each conversation an owner
Reception may need to pass work between shifts or send a request to a colleague. An assignment and a concise note can explain what the person needs, what has been said and what still needs confirmation.

Avoid copying unnecessary personal details into a note. For routine coordination, ask only for what the clinic needs to complete the administrative task. Review access and data-handling requirements before introducing a new provider to sensitive information.

## Keep AI within approved information
If the clinic uses an AI agent, start with a small administrative knowledge set. Test unknown questions, ambiguous wording and a request to speak to a person. Check that the agent does not invent availability, interpret symptoms or imply that a clinician has reviewed a message.

A useful handover gives staff the conversation and enough context to act. The clinic should define an appropriate response process for messages requiring professional review, including its own urgent-contact procedures.

## Pilot with synthetic examples
Use made-up enquiries rather than real patient information during the first evaluation. Try an opening-hours question, a preferred appointment time, a change request and a question outside scope. Test both languages if needed.

Have the receiving staff member continue each conversation. Review whether they understand the next step, can find the original messages and know where to confirm details. A successful isolated reply is not enough to prove a reliable reception process.

## Review before expanding
After a limited pilot, review unanswered enquiries, unclear ownership, incorrect information and any unnecessary data collection. Check whether the clinic's process and the provider's contractual and security arrangements meet the clinic's requirements before expanding use.
